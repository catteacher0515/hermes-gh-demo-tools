# gh-demo-x 决策卡改版设计

日期：2026-05-23

## 背景

旧版 `gh-demo-x` 已经解决了两个关键问题：

1. 不再让模型自由联网猜仓库状态，而是先做事实抓取。
2. 不再把 README 正文整段抄进最终 Markdown。

但产物仍然偏“工程理解卡”，不够像创作者真实使用的“选题决策卡”。

## 目标

让 `gh-demo-x` 的最终产物更贴近内容创作场景，服务下面这类决策：

- 这个仓库值不值得花 30 分钟体验
- 这题更像提效工具、提示词库还是技术项目
- 它对用户有没有传播张力
- 它能不能长出第一手体验
- 哪些坑点 / 对比对象 / 体验成本需要提前知道

## 用户偏好

### 优先级

- 最高优先级：能提高效率，且用户自己可能真会用
- 高优先级：能提高效率，即使用户自己不一定长期用，但大量打工人会用
- 次优先：好玩，但要足够轻、足够容易体验
- 低优先：硬核技术仓库

### 明确减分项

- 需要很强技术背景才能讲清
- 很难跑起来
- 很难形成第一手细节
- 传播面窄，只能写给少数开发者

### 额外判断

- 工具体验很重要，但工具体验差不等于仓库价值低
- 一些提示词库 / 方法库 / 原则库，即使不好“上手玩”，仍然可能有高传播价值
- 对比评测只有在天然存在对比对象时才需要出现

## 新的 9 项输出结构

1. 选题结论
2. 题材类型
3. 一句话题眼
4. 对用户的优先级
5. 工具体验价值
6. 传播张力
7. 值得提及的设计亮点
8. 你必须亲自验证的点
9. 体验投入等级 + 最终动作

## 设计细节

### 1. 选题结论

固定为：

- 值得写
- 待定
- 不值得写

### 2. 题材类型

用于区分不同仓库的价值来源，避免“工具体验弱”被误判为“仓库价值低”。

候选类型：

- 提效工具
- 好玩轻工具
- 方法库
- 提示词库
- 框架认知
- 技术项目

### 3. 一句话题眼

要求模型把“这篇内容最该抓的钩子”压缩成一句话，而不是重复 README 介绍。

### 4. 对用户的优先级

固定为：

- 最高
- 高
- 次
- 低

并说明原因：

- 是用户自己会用
- 还是虽然用户不一定用，但其读者会用

### 5. 工具体验价值

固定为：

- 高
- 中
- 低

强调：

- 这是重要信号
- 但不是一票否决项

### 6. 传播张力

固定为：

- 高
- 中
- 低

要求模型从内容传播角度判断是否容易被效率用户点开，而不是只看技术正确性。

### 7. 值得提及的设计亮点

只保留对普通内容读者有意义的设计 / 机制：

- 为什么这样设计
- 这样做给用户带来什么好处

避免深入硬核原理拆解。

### 8. 你必须亲自验证的点

这项应该综合：

- 体验坑点
- 用户坑点
- 安装 / 配置卡点
- 如果存在天然对比对象，也应放在这里

### 9. 体验投入等级 + 最终动作

投入等级：

- 低
- 中
- 高

最终动作：

- 入池
- 先观察
- 放弃

## 非目标

- 不输出 README 正文
- 不伪造第一手体验
- 不把“本地跑不通”简单等同于“不值得写”
- 不把硬核技术分析当成默认输出

## 实现要求

1. `gh-demo-x` 的 Hermes prompt 改成以上 9 项结构。
2. 对 Hermes 输出做轻量清洗，至少移除：
   - `(clarify timed out after 120s — agent will decide)`
3. 继续保留事实抓取优先架构。
4. 最终 Markdown 仍保持：
   - Repo
   - Generated
   - Stage
   - README 链接
   - 已验证事实
   - 判断结果
